# ADR-006: NixOS guest with a separate per-ticket execution boundary

- Status: accepted for implementation
- Date: 2026-09-02

## Context

JACK-K needs a reproducible host-independent runtime for its control plane and
a stronger boundary for arbitrary commands produced by coding agents. A Linux
host can provide KVM without making its mutable package set part of JACK-K's
runtime. NixOS provides pinned system composition and atomic generations, but a
single long-lived guest does not isolate one untrusted ticket from another or
from the control plane.

## Decision

Run the JACK-K control plane in a locked, headless NixOS qcow2 guest managed by
libvirt/QEMU on the Linux host. Keep explicitly classified persistent state on
allowlisted host-backed or dedicated data filesystems, outside the Nix store.
Run services from Nix package outputs under hardened, least-privilege systemd
units. Use the external secrets manager for application credentials and reserve
Nix-native secret material for non-duplicated boot-time needs.

Retain ADR-002's separate short-lived worker boundary for every L2 execution.
First deliver its rootless isolated runtime under JK-005, then evaluate a
Nix-declared microVM backend under JK-023. The worker backend remains an
implementation detail beneath the same authority, credential, network,
resource, teardown, verification, and publication contracts.

## Consequences

The OS and toolchain become reviewable and roll back atomically, and the guest
OS can be replaced independently of durable data. Operators must maintain KVM,
libvirt, image builds, mount labels, Nix packaging, and restore tests. Rollback
does not repair compromised persistent state. CLI packaging and native Node
dependencies add initial work, but mutable global installs are excluded because
they would defeat runtime reproducibility.
